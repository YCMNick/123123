# 差一度：自動化測試與數值模擬

每次改遊戲前後跑一次：

```bash
npm run test:game
```

全部通過，代表「遊戲沒有壞掉」，而且「數值沒有崩潰」。共 70 項檢查，全程約 3 分鐘。

## 測了什麼

| 檔案 | 內容 |
|---|---|
| `smoke.test.js` | 用真的滑鼠、鍵盤走完整流程：首頁十大關卡、大關小關清單、倒數、拖曳和放大鏡、微調、暫停、過關、失敗重來、動物會動且轉正後安靜、十關畫面，以及 5 種螢幕寬度的版面 |
| `rules.test.js` | 規則和計分：十大關結構、0.5° 和 0.1° 的判定門檻、不吸附、三組連動、要倒過來才對的海市蜃樓、動物轉正時的叫聲、+2 秒只給一次、緊張模式的時間點、連輸放水、斜塔只有過關才計分、三種難度、結算評語（每大關五種等級、不連續重複）、Q 版音效（每件物品都有聲音、全部能正常合成）、計分公式、單調性 |
| `fuzz.test.js` | 極端操作：4 輪各 300 個隨機操作、超大角度、上萬次微調、狂拖、多指觸控、倒數中切換畫面、完成鍵連按 |
| `simulation.test.js` | 3 種難度 × 10 關 × 3 種玩家，各自動玩 200 局（共 18,000 局）：每局結果合法、參考機器人分數精確、14 項設計目標（含難度遞增、簡單模式新手也過得了、三種難度勝率依序遞減、掛機 0 分）、與基準線比較 |

## 看報告

跑完會產生 `test-results/game-sim/report.md`，內容有各關勝率、分數分布、星數分布、設計目標達成狀況，以及和基準線的差距。

- ❌ 強制目標沒達成：測試失敗。
- ⚠️ 已知問題：只提醒，不算失敗。這些就是之後優化要處理的項目。

## 改了數值之後

1. 跑 `npm run test:game`，看報告。
2. 如果數值改變是你**刻意**的，就跑 `npm run test:game:baseline` 更新基準線，並把 `baseline.json` 一起 commit。
3. 設計目標寫在 `balance.config.js`，可以調整。

## 三種難度

| 難度 | 名稱 | 算對齊的誤差 | 時間 | 放大鏡 | 分數 |
|---|---|---|---|---|---|
| 簡單 | 看到會歪頭 | 1.5° | ×1.35 | 度數＋往哪轉 | ×0.6 |
| 普通 | 忍不住伸手 | 0.5° | ×1 | 度數 | ×1 |
| 困難 | 不轉正睡不著 | 0.2° | ×0.85 | 只放大 | ×1.5 |

模擬時假設：放大鏡沒有度數時，玩家瞄得比較不準（誤差 ×1.6）；有方向提示時稍微準一點（×0.9）。

## 重要假設

模擬用的三種玩家（新手、一般、熟手）是**推估的模型**，不是真實玩家的數據。有了試玩數據後，請更新 `balance.config.js` 裡的 `PROFILES`。

## 可調參數

- `GAME_SIM_RUNS=200 npm run test:game`：減少模擬局數，跑得比較快。
- `GAME_FUZZ_ACTIONS=1000 npm run test:game`：增加隨機操作的次數。
